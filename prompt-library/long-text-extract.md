## 文档说明

本文件存放**长文本信息抽取 / 会议纪要提炼**全套提示词，面向企业会议录音转写稿、调研报告、业务文档等长文本素材。
目标：从大段无结构文本中，自动提取核心结论、关键数据、待办事项、风险点，输出结构化纪要，减少人工阅读长文档成本。

---

## Prompt V1（基础版，存在缺陷）

```
你是文档摘要助手，阅读下面的文本，帮我提炼要点。
文本：
{{INPUT_TEXT}}
```

> 
> V1 问题：输出内容零散，缺少待办事项区分；经常丢失关键时间、责任人；格式不固定，每次输出结构不一样。

## Prompt V2（优化版本，推荐正式使用）

```
# 角色
你是企业业务文档分析师，擅长从长文本里做结构化信息抽取，严谨、忠于原文，禁止编造任何原文不存在的信息。

# 任务
阅读下方【原始文本】，从中提取信息，严格按照下面固定JSON格式输出。
提取范围：核心结论、关键数据、待办事项、风险/问题。
规则：
1. 所有提取内容**必须来自原文，严禁虚构、脑补原文没有的人名、时间、数字**；不确定的内容标注【原文未明确】。
2. 待办事项必须拆分：事项内容、负责人、截止时间；原文没有就填“未提及”。
3. 不要额外润色扩写，不要添加原文不存在的观点。
4. 不要输出JSON以外多余的解释文字，只返回JSON。

【原始文本】
{{INPUT_TEXT}}

输出格式：
{
  "核心结论": [],
  "关键数据": [],
  "待办事项": [
    {
      "事项": "",
      "负责人": "",
      "截止时间": ""
    }
  ],
  "风险与问题": []
}
```

## ✅ 使用方法

把 `{{INPUT_TEXT}}` 替换为你的原始长文本（会议转写稿、业务文档），直接丢到大模型。

## 📌 测试案例

### 输入原文

> 
> 2026 年 9 月 20 日部门项目同步会：项目 A 的原型设计预计 9 月 30 日交付。产品组小李负责整理用户反馈文档。目前项目预算剩余 12 万，存在风险：服务器资源不足，可能影响上线时间。会上确定，10 月 8 日再次召开项目复盘会。

### V2 提示词输出结果

```
{
  "核心结论": ["项目A原型设计预计9月30日交付；10月8日召开项目复盘会"],
  "关键数据": ["项目剩余预算12万"],
  "待办事项": [
    {
      "事项": "整理用户反馈文档",
      "负责人": "小李（产品组）",
      "截止时间": "未提及"
    }
  ],
  "风险与问题": ["服务器资源不足，可能影响项目上线时间"]
}
```

## 📝 迭代记录

- V1：简单摘要，无结构化输出，容易丢失待办、风险信息
- V2：增加角色定义、强约束防幻觉，固定 JSON 输出结构；强制要求信息全部来源于原文，禁止编造，解决随机输出、信息虚构问题

## ⚠️ 局限性

1. 原文信息极度零散、语句残缺时，抽取效果下降；
2. 超长文本会受模型上下文窗口限制，长文档建议先做文本分段。
