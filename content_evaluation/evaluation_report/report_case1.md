## 一、测评基本信息

- 测试场景：长文本会议纪要信息抽取
- 测试 Prompt 版本：V1（基础版） VS V2（优化版）
- 评估工具：项目自研五维内容评估量表
- 测评素材：真实部门会议原始文稿

## 二、本次测试原始素材

```
2026年9月20日部门项目同步会：项目A的原型设计预计9月30日交付。产品组小李负责整理用户反馈文档。目前项目预算剩余12万，存在风险：服务器资源不足，可能影响上线时间。会上确定，10月8日再次召开项目复盘会。
```

## 三、V1 基础 Prompt 输出 & 打分

### V1 Prompt

```
你是文档摘要助手，阅读下面的文本，帮我提炼要点。
文本：{{INPUT_TEXT}}
```

### V1 AI 输出

```
本次会议明确了项目A的交付时间与后续工作，团队需要整理用户资料并做好服务器资源筹备，保障项目顺利上线。
```

### V1 打分结果（总分 46/100）

- 事实准确性：18/20（无编造内容）
- 信息完整性：6/20（**严重缺失**：剩余预算 12 万、复盘时间 10.8、负责人小李全部丢失）
- 逻辑严谨性：12/20（表述笼统、无结构化）
- 内容合规性：20/20
- 文风适配性：10/20（过于口语、无职场归档格式）

### V1 问题总结

1. 无结构化输出，信息全部揉成一团
2. 关键业务数据、责任人、时间节点大量丢失
3. 无法作为归档纪要使用，**完全不满足职场落地标准**

## 四、V2 优化 Prompt 输出 & 打分

### V2 AI 输出

```
{
  "核心结论": ["项目A原型设计预计9月30日交付；10月8日召开项目复盘会"],
  "关键数据": ["项目剩余预算12万"],
  "待办事项": [
    {
      "事项": "整理用户反馈文档",
      "负责人": "小李（产品组）",
      "截止时间": "未提及"
    }
  ],
  "风险与问题": ["服务器资源不足，可能影响项目上线时间"]
}
```

### V2 打分结果（总分 92/100）

- 事实准确性：20/20（100% 忠于原文，无幻觉）
- 信息完整性：18/20（核心信息全覆盖）
- 逻辑严谨性：20/20（结构化分层清晰）
- 内容合规性：20/20
- 文风适配性：14/20（格式标准，可直接归档）

## 五、版本迭代效果对比总结

1. **解决信息丢失问题**：从 “残缺摘要” 升级为 “全量结构化萃取”
2. **解决输出不标准问题**：自由文本 → 固定 JSON 职场格式，可直接入库归档
3. **彻底杜绝 AI 脑补幻觉**：强溯源约束，零编造
4. **大幅降低人工整理成本**：无需二次梳理重点

## 六、复盘优化结论

简单无约束 Prompt 无法满足企业业务落地，**职场 AI 应用必须：角色定义 + 结构化输出 + 事实约束 + 风险兜底**。
本案例验证了本项目整套 Prompt 优化体系、评估体系的实用性与落地价值。
